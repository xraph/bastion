A route defines how incoming requests are matched and forwarded to upstream targets. Each route has a path pattern, one or more targets, a protocol, and optional overrides for rate limiting, authentication, caching, timeouts and retries.

## RouteConfig

The `RouteConfig` struct is the primary way to define routes programmatically:

```go
type RouteConfig struct {
    // Path is the URL pattern to match (e.g., "/users/*", "/api/v1/orders/*").
    Path string

    // Methods limits the route to these HTTP methods. Empty matches every method.
    Methods []string

    // Targets is the list of upstream targets for this route.
    Targets []TargetConfig

    // StripPrefix removes the matched path prefix before forwarding.
    StripPrefix bool

    // AddPrefix is put in front of the path before forwarding.
    AddPrefix string

    // RewritePath is a regex rewrite rule, "pattern:replacement", run on
    // the path after StripPrefix and AddPrefix.
    RewritePath string

    // Headers adds, sets and removes request headers sent upstream.
    Headers HeaderPolicy

    // Protocol is the proxy protocol: ProtocolHTTP, ProtocolWebSocket,
    // ProtocolSSE, ProtocolGRPC or ProtocolGraphQL.
    Protocol RouteProtocol

    // Priority orders matching. Higher wins.
    Priority int

    // Enabled controls whether this route is active.
    Enabled bool

    // Retry overrides the global retry configuration for this route.
    Retry *RetryConfig

    // Timeout overrides the global upstream timeouts for this route.
    Timeout *TimeoutConfig

    // RateLimit overrides the global rate limit for this route.
    RateLimit *RateLimitConfig

    // Auth sets route-specific authentication requirements.
    Auth *RouteAuthConfig

    // Cache sets route-specific response caching policy.
    Cache *RouteCacheConfig

    // TrafficPolicy holds canary, blue-green, A/B or mirror rules.
    // It is stored with the route, but the proxy doesn't apply it yet.
    TrafficPolicy *TrafficPolicy

    // Metadata is a free-form map for custom route annotations.
    Metadata map[string]any

    // ServiceName associates the route with a logical service, so it can
    // contribute to the aggregated OpenAPI spec.
    ServiceName string

    // OpenAPISpec is the URL of the upstream service's OpenAPI spec.
    OpenAPISpec string
}
```

`TargetConfig` has `URL`, `Weight`, `Tags`, `Metadata` and `TLS`. There is no per-route load balancing field; the strategy is set for the whole gateway.

### Registering routes

Routes are registered via the `WithRoute` option function:

```go
func register(app forge.App) error {
    return app.RegisterExtension(gateway.New(
        bastion.WithRoute(bastion.RouteConfig{
            Path: "/users/*",
            Targets: []bastion.TargetConfig{
                {URL: "http://user-service:8080", Weight: 1},
            },
            StripPrefix: true,
            Protocol:    bastion.ProtocolHTTP,
            Enabled:     true,
        }),
    ))
}
```

`gateway.New` comes from `github.com/xraph/bastion/gateway`. `extension.New` takes the same options and adds a persistent route store.

## Path matching

Bastion uses path patterns to match incoming requests to routes. Patterns support these forms:

| Pattern | Matches | Example |
|---------|---------|---------|
| `/users/*` | Any path starting with `/users/` | `/users/42`, `/users/42/profile` |
| `/api/v1/orders/*` | Any path starting with `/api/v1/orders/` | `/api/v1/orders/123` |
| `/health` | Exact match only | `/health` |

The `*` wildcard matches one or more path segments. The first matching route in the route table wins, and the table is ordered as described below.

### Path conflicts

When several routes could match a request, the route table decides. Higher `Priority` comes first. At the same priority, manual routes come before FARP routes, which come before discovered ones. After that, the route with the longer path pattern wins, so `/portal/*` matches before `/*`. Routes you define in code or YAML get 100 added to their `Priority`, so they beat discovered routes.

## Protocol selection

Each route specifies a protocol that determines how requests are proxied:

```go
const (
    ProtocolHTTP      RouteProtocol = "http"
    ProtocolWebSocket RouteProtocol = "websocket"
    ProtocolSSE       RouteProtocol = "sse"
    ProtocolGRPC      RouteProtocol = "grpc"
    ProtocolGraphQL   RouteProtocol = "graphql"
)
```

| Protocol | Use case |
|----------|----------|
| `ProtocolHTTP` | Standard HTTP/HTTPS API traffic. Also handles WebSocket upgrades automatically. |
| `ProtocolWebSocket` | Dedicated WebSocket routes where all traffic is WebSocket. |
| `ProtocolSSE` | Server-Sent Events streaming endpoints. Disables response buffering. |
| `ProtocolGRPC` | gRPC services. Forwards HTTP/2 frames including trailers. |
| `ProtocolGraphQL` | GraphQL services. Proxied like HTTP; the GraphQL plugin acts on these routes. |

For most services, `ProtocolHTTP` is the right choice. It handles both regular HTTP requests and WebSocket upgrade requests transparently.

## Strip prefix

When `StripPrefix` is `true`, Bastion removes the matched path prefix before forwarding the request to the upstream.

```go
// Route: /users/* with StripPrefix: true
// Request:  GET /users/42/profile
// Upstream: GET /42/profile

// Route: /users/* with StripPrefix: false
// Request:  GET /users/42/profile
// Upstream: GET /users/42/profile
```

This is useful when the upstream service does not expect the gateway's path prefix. Most microservice deployments use `StripPrefix: true`.

## Path rewriting

The path the upstream sees is built in three steps, in this order:

1. `StripPrefix` removes the route's path prefix.
2. `AddPrefix` is put in front of what's left.
3. `RewritePath` runs a regex rule on the result.

The rule is `"pattern:replacement"`, split at the first colon, so the pattern can't contain one. The replacement can use capture groups (`$1`). A rule that doesn't compile leaves the path as it is.

```go
route := bastion.RouteConfig{
    Path:        "/legacy/*",
    StripPrefix: true,
    AddPrefix:   "/api",
    RewritePath: "^/api/v1/(.*):/api/v2/$1",
}
// Request:  GET /legacy/v1/orders?page=2
// Upstream: GET /api/v2/orders?page=2
```

The query string is forwarded unchanged. The rewrite applies to HTTP, SSE, WebSocket and gRPC requests alike.

## Enable and disable

Routes have an `Enabled` field that controls whether they accept traffic:

```go
route := bastion.RouteConfig{
    Path:    "/users/*",
    Enabled: true, // route is active
}
```

Disabled routes return `404 Not Found` as if they do not exist. You can enable and disable routes at runtime through the admin API:

```
POST /bastion/api/routes/:id/enable
POST /bastion/api/routes/:id/disable
```

## Static vs discovered routes

Bastion supports two sources of routes:

**Static routes** are defined in code (via `WithRoute`) or in YAML configuration. They are loaded at startup and persist across restarts.

**Discovered routes** are created automatically by the FARP service discovery integration. When a new service registers itself via FARP, Bastion creates a route for it. When the service deregisters, the route is removed.

Static routes take precedence over discovered routes when paths overlap. Discovered routes are tagged with metadata indicating their source.

## Per-route overrides

Several global settings can be overridden at the route level:

### Rate limiting

```go
route := bastion.RouteConfig{
    Path: "/uploads/*",
    RateLimit: &bastion.RateLimitConfig{
        Enabled:        true,
        RequestsPerSec: 10,
        Burst:          5,
    },
}
```

### Load balancing

A route can't override the load balancing strategy. You set it for the whole gateway:

```go
opt := bastion.WithLoadBalancing(bastion.LoadBalancingConfig{
    Strategy: bastion.LBLeastConnections,
})
```

A route can still weight its targets with `TargetConfig.Weight`, which the weighted strategies use.

### Authentication

```go
route := bastion.RouteConfig{
    Path: "/admin/*",
    Auth: &bastion.RouteAuthConfig{
        Enabled:   true,
        Providers: []string{"admin-token"}, // the name you registered the provider under
        Scopes:    []string{"admin"},
    },
}
```

Route auth only runs when gateway auth is on (`auth.enabled`). `SkipAuth: true` opens one route on a gateway that otherwise requires auth.

### Response caching

```go
route := bastion.RouteConfig{
    Path: "/products/*",
    Cache: &bastion.RouteCacheConfig{
        Enabled: true,
        TTL:     5 * time.Minute,
    },
}
```

### Timeout

```go
route := bastion.RouteConfig{
    Path: "/reports/*",
    Timeout: &bastion.TimeoutConfig{
        Read:  60 * time.Second,
        Write: 2 * time.Minute,
    },
}
```

`Read` is how long the gateway waits for the upstream's response headers, `Connect` bounds the dial, and `Idle` is how long a pooled connection may sit unused. A field you leave at zero takes the gateway-wide value from `timeouts`. `Write` bounds how long sending the request body upstream may take, so a client that stalls mid-upload can't hold the request open. It only applies when the route sets it. A route that hits a timeout answers 502.

These apply to HTTP routes. WebSocket, SSE and gRPC traffic is long-lived and doesn't read them: WebSocket dials use `web_socket.handshake_timeout`, gRPC uses the gateway-wide `connect` and `idle` plus the `Grpc-Timeout` header the client sends, and SSE has fixed settings of its own.

### Retry policy

```go
route := bastion.RouteConfig{
    Path: "/payments/*",
    Retry: &bastion.RetryConfig{
        Enabled:          true,
        MaxAttempts:      3,
        Backoff:          bastion.BackoffExponential,
        InitialDelay:     100 * time.Millisecond,
        MaxDelay:         5 * time.Second,
        Multiplier:       2.0,
        Jitter:           true,
        RetryableStatus:  []int{502, 503, 504},
        RetryableMethods: []string{"GET", "HEAD", "OPTIONS"},
    },
}
```

The route's `Retry` replaces the global `retry` block for that route. Note that the proxy doesn't retry requests yet: the retry policy is stored and validated, but nothing in the request path acts on it.

## YAML route configuration

Routes can also be defined in YAML:

```yaml
bastion:
  routes:
    - path: "/users/*"
      targets:
        - url: "http://user-service:8080"
          weight: 1
      strip_prefix: true
      protocol: http
      enabled: true
      timeout:
        read: 30s
        write: 30s
      rate_limit:
        enabled: true
        requests_per_sec: 100
        burst: 20
      cache:
        enabled: true
        ttl: 5m
```

A route has no load balancing key of its own. You set the strategy for the whole gateway under `load_balancing.strategy`.
