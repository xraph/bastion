description: Programmatic and YAML configuration for Bastion.

Bastion can be configured programmatically via option functions, declaratively via YAML/JSON configuration files, or through a combination of both. Config is read once, at `Register`. At runtime you change routes through the admin API; nothing reloads the config file.

## Programmatic configuration

Bastion uses the functional options pattern. Options are passed to `gateway.New` (or `extension.New`):

```go
gateway.New(
    bastion.WithBasePath("/api"),
    bastion.WithRoute(bastion.RouteConfig{
        Path:    "/users/*",
        Targets: []bastion.TargetConfig{
            {URL: "http://user-service:8080", Weight: 1},
        },
        StripPrefix: true,
        Protocol:    bastion.ProtocolHTTP,
        Enabled:     true,
    }),
    bastion.WithCircuitBreaker(bastion.CircuitBreakerConfig{
        Enabled:          true,
        FailureThreshold: 5,
        ResetTimeout:     30 * time.Second,
    }),
    bastion.WithRateLimiting(bastion.RateLimitConfig{
        Enabled:        true,
        RequestsPerSec: 1000,
        Burst:          100,
    }),
    bastion.WithHealthCheck(bastion.HealthCheckConfig{
        Enabled:  true,
        Interval: 10 * time.Second,
        Path:     "/health",
    }),
    bastion.WithDiscoveryEnabled(true),
    bastion.WithDiscoveryAutoPrefix(true),
    bastion.WithDashboard(bastion.DashboardConfig{
        Enabled:  true,
        BasePath: "/bastion",
        Realtime: true,
    }),
)
```

### Available option functions

| Option | Description |
|--------|-------------|
| `WithBasePath(path)` | Sets the base URL prefix for all gateway routes (default: `""`) |
| `WithRoute(cfg)` | Adds a static route. Can be called multiple times. |
| `WithCircuitBreaker(cfg)` | Configures global circuit breaker settings |
| `WithRateLimiting(cfg)` | Configures global rate limiting |
| `WithHealthCheck(cfg)` | Configures active health checking |
| `WithDiscovery(cfg)` | Replaces the whole FARP discovery block; the `WithDiscovery...` setters change one field each |
| `WithDashboard(cfg)` | Replaces the whole dashboard block (admin API, WebSocket hub, admin token) |
| `WithAdminToken(token)` | Requires `Authorization: Bearer <token>` on the admin API |
| `WithAdminMiddleware(mw...)` | Adds your own middleware in front of the admin API |
| `WithTLS(cfg)` | Configures default upstream TLS settings |
| `WithCORS(cfg)` | Configures CORS headers |
| `WithIPFilter(cfg)` | Configures IP allow/deny lists |
| `WithAuth(cfg)` | Configures global authentication |
| `WithCaching(cfg)` | Configures global response caching |
| `WithRetry(cfg)` | Configures global retry policy |
| `WithTimeouts(cfg)` | Sets the global upstream timeouts (`TimeoutConfig`) |
| `WithConfig(cfg)` | Replaces the whole config |

The gateway logs through the Forge app's logger; there's no logger option.

## YAML configuration

Bastion reads configuration from Forge YAML config files under `extensions.bastion`, falling back to a top-level `bastion` key:

```yaml
bastion:
  enabled: true
  base_path: "/api"
  routes:
    - path: "/users/*"
      targets:
        - url: "http://user-service:8080"
          weight: 1
      strip_prefix: true
      protocol: http
      enabled: true
    - path: "/orders/*"
      targets:
        - url: "http://order-service:8080"
          weight: 1
      strip_prefix: true
      protocol: http
      enabled: true
  circuit_breaker:
    enabled: true
    failure_threshold: 5
    reset_timeout: 30s
  rate_limiting:
    enabled: true
    requests_per_sec: 1000
    burst: 100
  health_check:
    enabled: true
    interval: 10s
    path: "/health"
    timeout: 5s
  discovery:
    enabled: true
    auto_prefix: true
  dashboard:
    enabled: true
    base_path: "/bastion"
    realtime: true
```

When you use both, the order is defaults, then YAML, then the options you pass in code. A key the YAML leaves out keeps its default. An option overrides only the fields it sets, so `WithAdminToken` replaces the token and leaves the rest of the YAML dashboard block alone. Options that add to a list, like `WithRoute` and `WithAdminMiddleware`, add to what the YAML already lists.

## Configuration keys reference

Keys are the snake_case names below, under `extensions.bastion` or the top-level `bastion` key. Defaults are the values Bastion uses when you leave a key out.

### Top-level

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `true` | Enable or disable the entire gateway |
| `base_path` | `string` | `""` | Base URL prefix for all proxied routes |

### Routes (`routes[]`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `path` | `string` | none | URL pattern to match (required) |
| `methods` | `[]string` | all | HTTP methods the route accepts |
| `targets` | `[]object` | none | Upstream targets (required, at least one) |
| `targets[].url` | `string` | none | Target base URL |
| `targets[].weight` | `int` | `1` | Relative traffic weight |
| `strip_prefix` | `bool` | `false` | Remove matched prefix before forwarding |
| `add_prefix` | `string` | `""` | Put in front of the path after `strip_prefix` |
| `rewrite_path` | `string` | `""` | Regex rule, `"pattern:replacement"`, run after `add_prefix` |
| `protocol` | `string` | `"http"` | Proxy protocol: `http`, `websocket`, `sse`, `grpc` |
| `enabled` | `bool` | `false` | Whether the route is active. A route you don't set to `true` is skipped |
| `timeout` | `object` | global `timeouts` | Override with `connect`, `read`, `write`, `idle` durations. A field you leave out takes the global value, except `write`, which only applies when the route sets it. HTTP routes only |
| `rate_limit` | `object` | global `rate_limiting` | Override with the same keys as `rate_limiting` |
| `retry` | `object` | global `retry` | Override with the same keys as `retry` |

### Timeouts (`timeouts`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `connect` | `duration` | `10s` | Upstream connect timeout |
| `read` | `duration` | `30s` | How long to wait for the upstream's response headers |
| `write` | `duration` | `30s` | Not enforced gateway-wide. Set `write` on a route to bound how long sending the request body may take |
| `idle` | `duration` | `90s` | How long a pooled upstream connection may sit unused |

### Load balancing (`load_balancing`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `strategy` | `string` | `"roundRobin"` | `roundRobin`, `weightedRoundRobin`, `random`, `leastConnections`, `consistentHash` |
| `consistent_key` | `string` | `""` | Request header to hash on for `consistentHash`. Without it the client address is used |

### Traffic split (`traffic_split`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `false` | Apply routes' traffic policies (canary, blue-green, A/B, weighted, mirror). Off ignores them |

### Circuit breaker (`circuit_breaker`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `true` | Enable circuit breakers |
| `failure_threshold` | `int` | `5` | Failures before opening the circuit |
| `failure_window` | `duration` | `60s` | Window the failures are counted over |
| `reset_timeout` | `duration` | `30s` | Time to wait before transitioning from open to half-open |
| `half_open_max` | `int` | `3` | Requests allowed through while half-open |

### Rate limiting (`rate_limiting`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `false` | Enable rate limiting |
| `requests_per_sec` | `float64` | `1000` | Token refill rate (requests per second) |
| `burst` | `int` | `100` | Maximum burst size (token bucket capacity) |
| `per_client` | `bool` | `false` | Keep a separate bucket per client |
| `key_header` | `string` | `""` | Header that identifies the client for per-client limits |

### Health check (`health_check`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `true` | Enable active health probes |
| `interval` | `duration` | `10s` | Time between health check requests |
| `timeout` | `duration` | `5s` | Health check request timeout |
| `path` | `string` | `""` | HTTP path to probe on each target. Empty probes `/_/health` and keeps a target that answers 404 |
| `failure_threshold` | `int` | `3` | Failed probes before a target is marked unhealthy |
| `success_threshold` | `int` | `2` | Passing probes before it is marked healthy again |
| `enable_passive` | `bool` | `true` | Also count failures seen on live traffic |
| `passive_fail_threshold` | `int` | `5` | Live-traffic failures before a target is marked unhealthy |

### Discovery (`discovery`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `true` | Enable FARP service discovery |
| `poll_interval` | `duration` | `30s` | How often to poll for services |
| `watch_mode` | `bool` | `true` | Not implemented yet. With it on, Bastion logs a warning and polls every `poll_interval` |
| `auto_prefix` | `bool` | `true` | Auto-create route prefixes from service names |
| `prefix_template` | `string` | `"/{{.ServiceName}}"` | Template for the generated prefix |
| `strip_prefix` | `bool` | `true` | Strip the generated prefix before forwarding |

### Dashboard (`dashboard`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `true` | Enable the admin REST API |
| `base_path` | `string` | `"/gateway"` | Base path for the admin API routes |
| `realtime` | `bool` | `true` | Enable WebSocket real-time event stream |
| `admin_token` | `string` | `""` | Bearer token every admin API request has to carry |
| `allow_unauthenticated_admin` | `bool` | `false` | Silence the warning for an admin API with no auth |

### Authentication (`auth`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `false` | Enable gateway-level authentication |
| `default_policy` | `string` | `""` | With no providers configured, `allow` lets requests through. Anything else answers 401 |
| `providers` | `[]string` | `[]` | Auth providers to try in order. The first one that passes lets the request through |
| `forward_headers` | `bool` | `true` | Forward identity headers to the upstream |

### TLS (`tls`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `false` | Enable upstream TLS |
| `ca_cert_file` | `string` | `""` | CA certificate for upstream verification |
| `client_cert_file` | `string` | `""` | Client certificate for mTLS |
| `client_key_file` | `string` | `""` | Client key for mTLS |
| `insecure_skip_verify` | `bool` | `false` | Skip certificate verification (development only) |
| `min_version` | `string` | `"1.2"` | Minimum TLS version |
| `reload_interval` | `duration` | `0` | How often to reload certificates from disk (0 = never) |

### Retry (`retry`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `true` | Enable retries |
| `max_attempts` | `int` | `3` | Maximum attempts, the first included (1 to 10) |
| `backoff` | `string` | `"exponential"` | Backoff strategy: `exponential`, `linear`, `fixed` |
| `initial_delay` | `duration` | `100ms` | Initial delay between retries |
| `max_delay` | `duration` | `5s` | Maximum delay cap |
| `multiplier` | `float64` | `2.0` | Delay multiplier for `exponential` |
| `jitter` | `bool` | `true` | Add randomized jitter to delays |
| `retryable_status` | `[]int` | `[502, 503, 504]` | Upstream statuses that trigger a retry |
| `retryable_methods` | `[]string` | `[GET, HEAD, OPTIONS]` | Methods that are safe to retry |
| `budget_percent` | `float64` | `20` | Cap on retries as a percentage of each target's requests over the last 10s, with a floor of 3 retries per window. `0` is unlimited |

### Cache (`caching`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enabled` | `bool` | `false` | Enable response caching |
| `default_ttl` | `duration` | `5m` | Default cache entry time-to-live |
| `max_size` | `int` | `1000` | Maximum number of cached entries |
| `methods` | `[]string` | `[GET, HEAD]` | Methods whose responses are cached |
| `vary_by` | `[]string` | `[]` | Request headers that go into the cache key |

## Changing configuration at runtime

The config file is read once, during `Register`. Editing it while the gateway runs changes nothing until you restart. (The root package has a `ConfigWatcher` type that polls a file and calls you back with the new `Config`, but the extension never starts one and there's no method to apply a new `Config` to a running gateway.)

What you can change at runtime:

- Routes, through the admin REST API:

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/gateway/api/routes` | Create a new route |
| `PUT` | `/gateway/api/routes/:id` | Update an existing route |
| `DELETE` | `/gateway/api/routes/:id` | Remove a route |
| `POST` | `/gateway/api/routes/:id/enable` | Enable a route |
| `POST` | `/gateway/api/routes/:id/disable` | Disable a route |

  Changes take effect immediately. Discovered routes can't be edited, because the next discovery poll would overwrite them.
- Discovered routes, which follow what the discovery extension reports on every poll.
- TLS certificate contents, which are re-read from disk every `tls.reload_interval` when you set one.

## Per-route config overrides

Many global settings can be overridden at the route level. Route-level settings take precedence over global settings.

```yaml
bastion:
  rate_limiting:
    enabled: true
    requests_per_sec: 1000
    burst: 100
  routes:
    - path: "/uploads/*"
      targets:
        - url: "http://upload-service:8080"
      rate_limit:
        enabled: true
        requests_per_sec: 10     # stricter limit for uploads
        burst: 5
    - path: "/api/*"
      targets:
        - url: "http://api-service:8080"
      # inherits the global rate limit (1000 req/s)
```

Overridable settings: `rate_limit`, `timeout`, `retry`, `auth`, `cache`.
