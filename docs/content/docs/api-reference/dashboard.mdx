Bastion's dashboard is a React plugin, `packages/plugin-bastion`, that runs inside the Forge dashboard shell. It lives in the `forge-dashboard` repo. This repo has no UI code: the extension registers a `bastion` contract contributor (`extension/contract`) and the plugin calls it.

## Adding the plugin

Import it into your shell and put it in the plugin list:

```tsx
import bastionPlugin from "@forge-go/dashboard-plugin-bastion"

const plugins = [corePlugin, bastionPlugin]
```

The plugin's pages use Tailwind classes of their own. If your shell lists its sources with `@source`, add `@source "<path to>/packages/plugin-bastion/src";` next to the others.

On the Go side you do nothing extra. `extension.Extension` registers the contributor through `RegisterContractContributor`, and the shell finds it. If your code still imports `github.com/xraph/bastion/dashboard`, delete that import, because the package is gone. The record of that move is in [MIGRATION.md](https://github.com/xraph/bastion/blob/main/MIGRATION.md).

## Pages

Five pages exist today.

| Page | What you can do |
|------|-----------------|
| Overview | See requests, errors, latency, open circuits and upstream health |
| Routes | Browse every route, create one with New route, or run Refresh discovery |
| Route detail | Read one route, edit it, disable it or delete it |
| Route editor | Create or change a manual route |
| Upstreams | See each target with its health and circuit state |

Traffic, health, circuits, services, API explorer and config pages are coming. Their intents already exist (see below), so the data is there once the pages land.

## Contract intents

The contributor answers 9 queries and 7 commands. Queries are read only. Commands change state and tell the shell which cached queries to refetch.

| Intent | Kind | Used by |
|--------|------|---------|
| `overview.stats` | query | Overview |
| `traffic.stats` | query | Traffic page (coming) |
| `circuits.list` | query | Circuits page (coming) |
| `routes.list` | query | Routes |
| `routes.detail` | query | Route detail, route editor |
| `upstreams.list` | query | Upstreams |
| `services.list` | query | Services page (coming) |
| `openapi.summary` | query | API explorer page (coming) |
| `config.detail` | query | Config page (coming) |
| `routes.create` | command | Route editor |
| `routes.update` | command | Route editor |
| `routes.delete` | command | Route detail |
| `routes.setEnabled` | command | Route detail (disable and enable) |
| `discovery.refresh` | command | Routes (Refresh discovery) |
| `openapi.refresh` | command | API explorer page (coming) |
| `circuits.reset` | command | Circuits page (coming) |

The manifest is `extension/contract/manifest.yaml`. It also sets how long each query stays fresh, from 5 seconds for stats and circuits to 60 seconds for config.

Discovered routes (from FARP or service discovery) are read only. Commands that edit, delete, enable or disable one are refused, because the next discovery update would undo the change.

## Configuring the gateway side

`DashboardConfig` no longer controls a UI, but it still gates the REST API, the WebSocket hub and the OpenAPI endpoints. You set it the same way as before.

### Programmatic

```go
import "github.com/xraph/bastion"

bastion.WithDashboard(bastion.DashboardConfig{
    Enabled:  true,
    BasePath: "/gateway",
    Realtime: true,
})
```

### YAML

```yaml
bastion:
  dashboard:
    enabled: true
    base_path: /gateway
    realtime: true
```

### Configuration Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `Enabled` | `bool` | `true` | Gates the admin REST API, the WebSocket hub and the OpenAPI/AsyncAPI endpoints |
| `BasePath` | `string` | `"/gateway"` | URL prefix for those endpoints |
| `Title` | `string` | `"Forge Gateway"` | Unused |
| `Realtime` | `bool` | `true` | Gates the WebSocket hub at `BasePath` + `/ws` |

The React dashboard does not depend on any of these. It talks to the contract contributor, not to the REST API, so it keeps working with `Enabled: false`.

## Customization

### Custom Base Path

Change where the REST API, WebSocket and OpenAPI endpoints are mounted:

```go
bastion.WithDashboard(bastion.DashboardConfig{
    Enabled:  true,
    BasePath: "/admin/gateway",
})
```

Those endpoints get the prefix `/admin/gateway` instead of the default `/gateway`.

### Disabling Real-Time

For environments where WebSocket connections are not available (some reverse proxies, serverless):

```go
bastion.WithDashboard(bastion.DashboardConfig{
    Enabled:  true,
    Realtime: false,
})
```

The WebSocket hub is not started. The React dashboard doesn't use it, so nothing changes there.

### Turning off the REST API

```go
bastion.WithDashboardEnabled(false)
```

This turns off the admin REST API, the WebSocket hub and the OpenAPI endpoints. The gateway proxy keeps working, and so does the React dashboard.
